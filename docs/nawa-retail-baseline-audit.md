# تدقيق أساس Nawa Retail

## نقطة الأساس

نقطة الاستقرار المرجعية هي `e0e2d5e5`، وتحتوي بالفعل على أساس B2B Retailer يعمل فوق دورة التجارة والتوزيع الحالية.

| المجال | الحالة | الدليل الحالي |
|---|---|---|
| الهوية والوصول | DONE | `b2b_retailer_accesses` مع حالة active/suspended/revoked وحارس `requireRetailerAccess`. |
| متعدد الموردين | DONE | يستخرج `listRetailerAccesses` العلاقات النشطة للمستخدم فقط ويفصل كل علاقة بمعرف access. |
| الكتالوج والتسعير | DONE | `getRetailerCatalog` يحل السعر خادمياً وفق قوائم الأسعار والعروض والمخزون والوحدات المسموحة. |
| العروض والتغليف | DONE | عروض B2B الموجهة والوحدات/التغليف المسموح بها موجودة، مع عدم كشف الكلفة أو المخزون الداخلي. |
| الطلب والسلة | DONE | السلة محلية ومفصولة بالوصول؛ الطلب يعيد حل السعر والعرض والمخزون خادمياً. |
| مراجعة المورد والتحويل | DONE | يتحول طلب B2B المقبول إلى Sales Order من دورة Nawa الحالية مرة واحدة فقط. |
| المتابعة والمستندات والذمم | DONE | Timeline الطلب، حالة التوصيل، والفواتير والرصيد المتبقي مقيدة بعلاقة التاجر. |
| المفضلة وإعادة الطلب | DONE | تفعيل/إلغاء المفضلة المقيدة بعلاقة الوصول، عرض المفضلة ومنتجات الطلب المتكرر، وإعادة الطلب عبر دورة B2B القائمة. |
| Outlets وتعدد مستخدمي التاجر | DONE | كيان `b2b_retailer_outlets` مع رمز فريد داخل المورد والعميل، حالة وموقع اختياري وسجل تدقيق وإدارة المالك. |
| تجربة Nawa Retail | DONE | المسار `/retailer` تجربة Mobile-first مستقلة بصرياً بمبدّل موردين وملخص وتبويبات للكتالوج والسلة والطلبات والمستندات. |
| تقارير وتصدير التاجر | DONE | تقرير شهري خادمي مقيد بعلاقة الوصول مع تنزيل CSV وPDF من نفس المجموعة المرئية. |
| PWA | DONE | manifest خاص بـRetail وعامل خدمة محصور في `/retailer` لا يخزن طلبات API أو بيانات التجارة. |

## قرار التنفيذ

لم يُعَد بناء كتالوج أو تسعير أو طلب أو تحويل أو Timeline قائم. ركزت التوسعة على Home تجارية، المفضلة/إعادة الطلب، outlets غير المعطلة، التقرير والتصدير المقيدين، وتجربة PWA أساسية لا تخزن بيانات B2B محلياً.
