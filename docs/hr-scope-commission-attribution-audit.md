# تدقيق نطاق بيانات HR وإسناد العمولات

## نقطة الأساس والنطاق

نقطة الأساس هي `b0bd87b4`. تستهدف هذه الدفعة فجوتين محددتين: تطبيق نطاق HR من العضوية خادمياً، وربط عمولة البيع بمصدر تشغيلي وموظف موثوق. لا تعيد بناء الخدمة الذاتية أو كشف البنك أو وثائق المركبات.

| المجال | الحالة | التنفيذ أو القرار |
|---|---|---|
| Organization Scope | DONE | كل حارس يمرر `organizationId` من عضوية المستخدم؛ جميع استعلامات الموظف والعمولة تتحقق منه. |
| Branch / Department / Employee scope model | DONE | توسع نوع `organization_memberships.dataScope` ليدعم `branchIds` و`departmentIds` و`employeeIds`، واستخدم الحارس `hrDataScope.ts` في إجراءات الحضور والإجازة والساعات الإضافية. |
| Self / Direct reports | DONE | الحارس يسمح بالذات أو التقرير المباشر فقط عندما يطلب العقد ذلك، مع بقاء صلاحية الراتب منفصلة. |
| Salary privacy | DONE | التقارير والرواتب وكشف البنك محكومة بصلاحيات `hr.payroll.*`؛ لا يضيف حارس الفريق صلاحية راتب. |
| Payroll scope | PARTIAL | منع تمرير موظف خارج النطاق في إجراءات HR المباشرة موجود. تشغيل فترة رواتب كاملة يبقى عملية على مستوى المؤسسة؛ لا يسمح بتشغيل فترة جزئية كي لا تتغير حالة الفترة عالمياً بصورة غير صحيحة. |
| Sales attribution | DONE | مصدر العمولة هو فاتورة صادرة، ومالكها هو `business_parties.assignedRepresentativeEmployeeId` بعد التحقق من المنظمة وموظف نشط. |
| Sales commissions | DONE | تطبق قاعدة بيع نشطة واحدة على أساس إجمالي الفاتورة بعد الإصدار، بمبلغ ثابت أو نسبة مئوية. |
| Source idempotency | DONE | القيد الفريد `(organizationId, sourceModule, sourceDocumentType, sourceDocumentId, employeeId)` وحراسة ما قبل الإدراج ومعالجة تعارض القاعدة تمنع التكرار. |
| Collection, delivery, return commissions | PARTIAL | مصادر التوزيع تحمل إسناد ممثل/سائق موثوق، لكن سياسة القواعد لا تميز بعد أساس التسليم الجزئي أو تحصيل السداد أو عكس المرتجع؛ لا تُستحدث عمولات لها قبل إضافة حقول أساس وعكس صريحة. |
| Finance posting | DONE | العمولة تدخل كـ payroll earning، ولا تنشأ حركة مالية مستقلة من حدث البيع؛ يحافظ هذا على منع double posting عند ترحيل الرواتب. |

## قرار معماري

لا يُقبل `employeeId` من العميل كإسناد عمولة لحدث بيع. يشتق النظام المستفيد من مندوب العميل المسجل في مؤسسة الفاتورة. تظل العمولات جزءاً من دخل الرواتب، ثم ترحل مع فترة الرواتب فقط. هذا يمنع الترحيل المالي المزدوج ويحفظ تاريخ الحدث من `issuedAt`.
