# إغلاق شركة Nawa Demo

**الحالة:** مكتمل وظيفياً مع قيود تحقق موثقة.  
**آخر تحقق تشغيلي:** 18 أغسطس 2026.  
**النطاق:** مؤسسة العرض `nawa-demo` فقط، من دون إنشاء حسابات مصادقة أو كلمات مرور تجريبية.

> شركة Nawa Demo هي مؤسسة معزولة قابلة للتهيئة وإعادة التهيئة والحذف. تعتمد على خدمات Nawa ومنطق الأعمال المعتمد بدلاً من بيانات واجهة ثابتة أو مسارات موازية.

## النتيجة التنفيذية

اكتملت بيانات العرض كدورة ERP مترابطة: هيكل المؤسسة وكتالوجها والتسعير، ثم المبيعات والمشتريات والمخزون، ثم التصنيع والجودة والتوزيع، وأخيراً Retail والموارد البشرية والرواتب والترحيل المالي. يظهر للمستخدم دليل عرض متعدد اللغات مع مؤشرات حيّة، بينما تبقى شارة **Demo** ومؤشراته محصورة بالمؤسسة النشطة الموسومة `isDemo = yes`.

| المجال | حالة الإغلاق | الدليل التشغيلي |
|---|---:|---|
| العزل والهوية | PASS | `isDemo` وسجل تشغيل Seed وسياق المؤسسة النشطة؛ لا توجد حسابات Demo اصطناعية. |
| الهيكل والبيانات الأساسية | PASS | 3 فروع، 4 مخازن، 14 دوراً، 30 منتجاً، 24 طرفاً تجارياً، 4 قوائم أسعار، ودفعات افتتاحية. |
| التجارة والمخزون | PASS | فواتير FEFO بحالات مدفوعة وجزئية ومتأخرة، وأمر شراء باستلام جزئي. |
| التصنيع والجودة | PASS | أوامر مكتمل ومعلّق جودة ومخطط، مع BOM ومخرجات وهدر وفحص جودة. |
| التوزيع | PASS | 4 مركبات و3 مناطق وجولة مكتملة بتسليم جزئي وتحصيل ووقود. |
| Nawa Retail | PASS | علاقة B2B نشطة، منفذ تاجر، وطلب يحسب السعر والتوافر والحد الائتماني في الخادم. |
| HR والرواتب والمالية | PASS | 4 موظفين وأقسام ومناصب وجدول وعقود وإجازة وبدل وعمولة وفترة رواتب مدفوعة وقيدان مرحلان. |
| دليل العرض والبوابات | PASS | شارة Demo ودليل `/demo-guide` ومؤشرات حية ومسارات بوابات متجاوبة بالعربية والفرنسية والإنجليزية. |
| Reset وDelete | PASS | تحقق عملي من الإزالة وإعادة الإنشاء وإعادة Seed، مع بقاء مؤسسة غير تجريبية دون تغيير. |

## بيانات العرض المتاحة

تُعرض الأرقام من قاعدة البيانات في لحظة التشغيل عبر استعلام مقيد بالمؤسسة النشطة؛ لذلك لا ينبغي التعامل معها كقِيَم ثابتة في واجهة المستخدم. بعد اختبار دورة الحياة الأخير، احتوت مؤسسة العرض المعاد إنشاؤها على أربع فواتير مبيعات، وطلب Retail واحد، وأربعة موظفين، وفترة رواتب واحدة. أمّا المؤسسة غير التجريبية الموجودة في بيئة الاختبار فلم تتغير عداداتها أثناء Reset أو Delete.

| البوابة | مسار الدخول | ما يُستعرض |
|---|---|---|
| التجارة والمخزون | `/commerce` | الفواتير والدفعات والـFEFO والمشتريات والاستلام. |
| التصنيع والجودة | `/manufacturing` | BOM وأوامر الإنتاج والمخرجات وفحص الجودة والهدر. |
| التوزيع والأسطول | `/distribution` | المركبات والمناطق والجولات والتسليم والتحصيل. |
| Nawa Retail | `/retailer` | العلاقة B2B والمنفذ والكتالوج والطلب التجاري. |
| الموارد البشرية والمالية | `/hr` ثم `/finance` | الموظفون والإجازة والعقود والرواتب والقيود المرحّلة. |
| دليل العرض | `/demo-guide` | مؤشرات حيّة ومسارات العرض وزر إعادة تجهيز السيناريو للمدير. |

## ضوابط العزل ودورة الحياة

تتطلب عملية Reset أن تكون المؤسسة الموسومة Demo ومتصلة بعضوية المستخدم. تحذف Reset البيانات التشغيلية ذات `organizationId` مع الإبقاء على المؤسسة والعضوية والأدوار والوحدات والإعدادات وسجل الـSeed، ثم تعيد بناء الأساس. تتطلب Delete عبارة التأكيد الدقيقة `DELETE NAWA DEMO`، وتحذف المؤسسة مع بياناتها وتصفّر تفضيل المؤسسة النشطة قبل إعادة إنشائها عند الحاجة.

المؤشرات الحية لا تكتفي بالعضوية في شركة العرض؛ بل تتحقق أولاً من سياق المؤسسة **النشطة** ثم من `isDemo = yes` وتطابق المعرّف. وعليه لا تظهر شارة Demo ولا مؤشرات العرض في واجهة مؤسسة تشغيلية حتى لو كان المستخدم نفسه يملك عضوية Demo.

## نتائج التحقق الفني

| الفحص | النتيجة | الملاحظة |
|---|---:|---|
| `pnpm check` | PASS | فحص TypeScript يمر دون أخطاء. |
| اختبار سياسة Demo | PASS | 10 اختبارات تغطي العزل والـSeed وسيناريو العمليات وRetail/HR/Payroll وقيد المؤسسة النشطة. |
| اختبار بوابات Nawa | PASS | 4 اختبارات تشمل مسار دليل العرض وظهور Demo المقيد. |
| اختبار دورة الحياة | PASS | Reset ثم إعادة Seed ثم Delete ثم إعادة إنشاء بمعرّف مؤسسة جديد، مع عدم تغير عدد المؤسسات غير التجريبية. |
| التحقق البصري | PASS | تمت مراجعة دليل العرض وصفحة البوابات على سطح المكتب والهاتف. |
| `pnpm lint` | PARTIAL | لا أخطاء؛ توجد 9 تحذيرات موروثة خارج نطاق Demo. |
| حزمة Vitest الكاملة | PARTIAL | اختبار المالية يجاوز المهلة أحياناً عند التشغيل المتوازي بسبب تزاحم قاعدة البيانات، ويجتاز منفرداً. التشغيل بفورك واحد يسبب تلوث DOM موروثاً بين اختبارات واجهة مستقلة؛ اختبار المظهر ينجح منفرداً. |

## تشغيل وإدارة العرض

لتهيئة السيناريو أو استكمال تشغيل متوقف، استخدم مشغل المشروع مع مستخدم مدير صالح:

```bash
DEMO_ACTOR_USER_ID=1 pnpm exec tsx scripts/seed-demo.mjs
```

ولتشغيل تحقق دورة الحياة الكامل في بيئة العرض فقط:

```bash
DEMO_ACTOR_USER_ID=1 pnpm exec tsx scripts/verify-demo-lifecycle.mjs
```

لا يوصى بتشغيل مشغل دورة الحياة في بيئة تحمل بيانات Demo يراجعها مستخدم أثناء التنفيذ، لأنه يحذف مؤسسة العرض ويعيد إنشاءها عمداً كجزء من اختبار Delete.

## القيود المتبقية والتوصية

أولوية المتابعة الوحيدة ليست في منطق Demo، بل في استقرار تشغيل الحزمة الكاملة للاختبارات: ينبغي فصل أو تسلسل اختبارات التكامل التي تشارك قاعدة البيانات، وتطبيق تنظيف DOM موحد بين ملفات اختبارات الواجهة. لا يمنع ذلك استخدام شركة العرض أو إعادة Seed أو Delete/Reset؛ لكنه يمنع اعتبار تقرير `pnpm test` المتوازي مؤشراً حتمياً وحيداً حتى معالجة تزامن الاختبارات الموروث.
