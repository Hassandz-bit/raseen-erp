# إغلاق أتمتة إصدار Service Worker

أصبحت عملية `pnpm build` تشغّل الآن `pnpm build:pwa` بعد انتهاء Vite وقبل تجميع الخادم. يقرأ المولد قالب `client/public/nawa-erp-sw.js` ويكتب نسخة مستقلة إلى `dist/public/nawa-erp-sw.js` باسم cache يحمل إصداراً جديداً لكل بناء. لا يتغير قالب التطوير ولا يحتاج الفريق إلى تعديل رقم يدوي.

| مصدر الإصدار | الأولوية |
|---|---|
| `NAWA_PWA_BUILD_ID` | قيمة صريحة لخط أنابيب النشر |
| `GITHUB_SHA` | أول 12 حرفاً عند وجود GitHub Actions |
| الوقت الحالي | إصدار فريد تلقائي عند غياب المتغيرين |

ينشئ المولد أيضاً `dist/public/nawa-pwa-build.json` لتسهيل تشخيص الإصدار المنشور. يحذف Service Worker عند التفعيل أي cache سابق يبدأ بـ`nawa-erp-shell-` ولا يطابق الإصدار الجديد، ويستمر في استبعاد API وطلبات الكتابة من التخزين المؤقت.

## التحقق

تم تشغيل المولد بإصداري `release-alpha` و`release-beta` في مخرجات معزولة، وأنتج اسمي cache وملفي بيان مختلفين كما هو متوقع. نجح `pnpm check` و`pnpm lint` و**239 اختباراً في 104 ملفات**. ما زال بناء Vite الكامل في sandbox يخضع لحد ذاكرة البيئة المعروف؛ لكن خطوة إصدار Service Worker اختُبرت مستقلة وستعمل بعد اكتمال Vite في بيئة النشر.
