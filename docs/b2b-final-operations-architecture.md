# التصميم التشغيلي النهائي لبوابة B2B

## دورة الطلب

يبقى `b2b_retailer_orders` السجل الأصلي لما طلبه المحل، ولا يعدل بعد الإرسال إلا عبر قرار مراجعة مدقق. تمر الحالة الخارجية بالمسار: **submitted → under_review → approved → converted** أو **rejected / cancelled**. عند الاعتماد، تحفظ الكميات والأسعار المؤكدة والفروق وأسبابها في سجل مراجعة منفصل. لا يصدر التحويل مخزوناً أو فاتورة؛ ينشئ **Sales Order** حقيقياً يحمل المصدر `b2b` ورابطاً فريداً بالطلب الأصلي، ثم يتابع تجهيز ومركبة وجولة وتسليم عبر العقود القائمة.

| مرحلة | السجل المسؤول | منع التكرار |
|---|---|---|
| طلب المحل | B2B Order | رقم طلب فريد داخل المؤسسة |
| مراجعة المؤسسة | B2B Review | تسلسل مراجعات مدقق مع السبب والفروق |
| التحويل | Sales Order | رابط فريد `b2bOrderId` على Sales Order |
| التجهيز والتوزيع | Sales Order / Distribution | مراجع فعلية فقط، ولا تنشئ بوابة المحل جولة جديدة |

## العروض

تسجل العروض في كيان تجاري منفصل وتُحسم خادمياً عند قراءة الكتالوج وعند إنشاء الطلب وعند اعتماد المؤسسة. يدعم النموذج الخصم النسبي والثابت والسعر الخاص وخصم الكمية وBuy X Get Y، مع استهداف العميل أو الشريحة أو المنطقة أو المنتج أو الدفعة وفترة الصلاحية. لا تقبل الواجهة قيمة خصم أو كمية مجانية أو معرف عرض بوصفه قراراً نهائياً.

تسمح عروض قرب الانتهاء فقط بعرض الاسم التجاري والسعر أو الكمية المجانية الناتجة للمحل المستهدف. لا تعرض تقييم المخاطر أو قيمة المخزون أو الكمية الداخلية أو اسم المخزن.

## الوصول والخصوصية

تستمر علاقة B2B النشطة كشرط مسبق لكل قراءة أو كتابة. التعليق أو الإلغاء يوقف الكتالوج والتسعير والطلبات والمستندات حتى مع بقاء جلسة المستخدم. تتحكم السياسة في ظهور الكتالوج والعروض والديون والمستندات، ولا تعرض البوابة موقع السائق أو مساره إلا عبر سياسة مستقلة وحالة تجارية مسموحة.
