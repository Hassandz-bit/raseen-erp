# تقرير الإغلاق: نطاق بيانات HR وعمولات المبيعات والتحصيل

## الحالة التنفيذية

**PARTIAL.** نقطة الأساس هي `b0bd87b4`، ونقطة العمل تشمل الترحيل `0033_cuddly_carlie_cooper.sql` الناتج عن تطبيع العضوية. أضيف حارس نطاق HR خادمي، وعمولة تلقائية من فاتورة مبيعات مؤكدة، وعمولة تلقائية من إيصال تحصيل توزيع، مع بقاء التوسعات التي لا تحمل مصادر أو أساساً موثوقاً معلنة صراحةً.

| بند التدقيق | الحالة | التطبيق الفعلي |
|---|---|---|
| Organization scope | PASS | تعتمد العقود والحارس وعمولات المصدر على `organizationId` من عضوية المستخدم فقط. |
| Branch / Department / Employee scope | PARTIAL | `dataScope` يدعم `branchIds` و`departmentIds` و`employeeIds`، وحارس `hrDataScope.ts` يتحقق منها قبل الحضور والإجازة والساعات الإضافية. لم يعمم بعد على كل عقد إدارة HR أو ملف موظف. |
| Self / Direct reports | PASS | الخدمة الذاتية تحل الموظف الحالي فقط، وقرارات الفريق تتحقق من المدير المباشر خادمياً. |
| Salary privacy | PASS | الرواتب وكشف البنك يتطلبان صلاحيات `hr.payroll.*` منفصلة؛ المدير لا يحصل عليها من نطاق فريقه. |
| Payroll scope | PARTIAL | تشغيل فترة الرواتب يبقى مؤسسياً لتفادي حساب جزئي يغير حالة فترة كاملة؛ لا يسمح الحارس بتجاوز موظف خارج النطاق في الإجراءات المباشرة. |
| Sales attribution | PASS | يشتق المستفيد من `assignedRepresentativeEmployeeId` للعميل داخل مؤسسة الفاتورة، ثم يتحقق وجود الموظف قبل الإنشاء. |
| Sales commission | PASS | عند إصدار فاتورة مؤهلة تطبق أول قاعدة بيع نشطة بمبلغ ثابت أو نسبة من `grandTotal`، وتستخدم `issuedAt` كتاريخ حدث. |
| Collection commission | PASS | عند إنشاء إيصال توزيع مؤهل تطبق أول قاعدة تحصيل نشطة على المبلغ المحصل الفعلي، وتستخدم `representativeEmployeeId` و`collectedAt`. |
| Delivery / partial / return reversal | PARTIAL | نموذج التسليم لا يحفظ قيمة تسليم صالحة لحساب عمولة جزئية على مستوى الحدث، والمرتجع لا يحمل أساس القيمة أو عملية عكس مرتبطة بقيد العمولة؛ لم تُخترع عمولات أو عكوس تخمينية. |
| Idempotency | PASS | يمنع القيد الفريد لمصدر العمولة مع حراسة قبل الإدراج ومعالجة تعارض القاعدة إنشاء عمولة ثانية للفاتورة أو الإيصال ذاته. |
| Payroll integration | PASS | العمولات تبقى `commission_entries` معتمدة، وتدخل مرة واحدة ضمن حساب فترة الرواتب واللقطة. |
| Finance double-posting | PASS | لا تنشئ أحداث البيع والتحصيل قيداً مالياً مستقلاً للعمولة؛ ترحل العمولة ضمن قيد فترة الرواتب فقط. |
| Bank export | PASS | يبقى التصدير لفترة مدفوعة وحساب صالح وصافي موجب وصلاحية مستقلة. |
| Vehicle regression | PASS | لم تمس الدفعة منطق وثائق المركبات؛ استمرت حزمة التوزيع ضمن الانحدار الكامل. |

## الحماية المباشرة للـAPI

تستدعي عقود تسجيل الحضور وتقديم الإجازة وإدخال الساعات الإضافية حارس نطاق خادمياً قبل استخدام `employeeId`. لذلك لا يكفي تمرير معرف موظف أو فرع أو قسم من العميل لتجاوز العضوية. يتيح الحارس الاستثناءات المحددة للذات أو التقرير المباشر فقط عندما يطلب العقد ذلك.

## العمولات والتدقيق

يسجل النظام `hr.commission_auto_sales_created` و`hr.commission_auto_collection_created` في سجل التدقيق، مع المصدر والمستفيد والقاعدة والأساس والمعدل والمبلغ وتاريخ الحدث. قاعدة العمولات الحالية تلتقط قاعدة نشطة واحدة لكل نوع مصدر؛ تعدد القواعد المتدرجة أو القانونية خارج النطاق.

## العناصر المتبقية

يبقى التطبيق الشامل لنطاق الفرع والقسم على جميع عمليات HR والرواتب **PARTIAL**، وكذلك عمولات التسليم الكامل والجزئي وعكس المرتجع بسبب نقص أساس مبلغ وإسناد تاريخي قابل للتدقيق في أحداث التسليم والمرتجع. لا تشمل الدفعة AI أو التوظيف أو البصمة أو قوانين الرواتب الخاصة بدولة أو محرك حصص وشرائح عمولات متقدم.
