# نموذج بوابة B2B للمحلات

## مبدأ الوصول

لا يمثل دخول المستخدم إلى Nawa ERP تصريحاً لرؤية كتالوج أي مؤسسة. تنشأ علاقة وصول صريحة تربط **مستخدماً واحداً** بعميل قائم في `business_parties` ومؤسسة محددة. يمكن للمستخدم امتلاك أكثر من علاقة نشطة، ولكن كل استعلام B2B يحدد علاقة واحدة نشطة ويعيد بيانات مؤسستها وعميلها فقط.

| الكيان | الغرض | ضوابط العزل |
|---|---|---|
| `b2b_retailer_accesses` | ربط المستخدم بالعميل والمؤسسة وقائمة الأسعار والمنطقة والسياسات | فريد لكل `organizationId + customerId + userId`، ولا يمر أي مسار B2B دون حالة `active` |
| `b2b_retailer_orders` | طلب تجاري مصدره بوابة المحل، مرجع فقط لعقود التجارة | ينتمي للعلاقة والعميل والمؤسسة؛ لا يمثل فاتورة ولا يصدر مخزوناً عند الإنشاء |
| `b2b_retailer_order_items` | المنتجات والكميات والسعر المحسوب خادمياً عند الإنشاء | يخزن نتيجة التسعير للمراجعة ويعاد حسابها عند إعادة الطلب |
| `b2b_retailer_favorites` | تفضيلات اختيارية مرتبطة بالمحل والمؤسسة | لا تكشف منتجات أو علاقة مؤسسة أخرى |

## قرار التسعير والكتالوج

تُعرض المنتجات النشطة فقط. تحسب الخدمة الخادمية السعر بالترتيب: سعر العميل في قائمة العميل المخصصة، ثم قائمة الشريحة، ثم قائمة المنطقة، ثم قائمة السعر المعينة، ثم السعر الافتراضي للمنتج. لا تقبل عملية الإرسال سعراً أو ضريبة أو إجمالياً من العميل. في البداية، تمثل العروض السعرية قوائم أسعار نشطة موجهة؛ ولا يُنشأ عرض تجريبي أو رصيد مخزون دقيق للمحل.

| مستوى الإفصاح | السلوك الخارجي |
|---|---|
| متاح | توجد كمية صالحة وفق قاعدة الأعمال المعلنة |
| منخفض | توجد كمية موجبة دون كشف الرقم الداخلي |
| غير متاح | لا توجد كمية متاحة ضمن المخازن التشغيلية |
| عند الطلب | سياسة المؤسسة لا تسمح بعرض حالة المخزون |

## الخصوصية والتوصيل

تحدد علاقة الوصول سياسة تتبع العميل: `off` أو `status_only` أو `eta_only` أو `limited_live`. لا يعرض التطبيق مسار السائق أو عملاء آخرين أو موقعاً مباشراً افتراضياً. عند عدم وجود حدث توزيع أو سياسة مناسبة، يعرض فقط حالة الطلب الخارجية المفهومة.

> الطلب B2B يسجل كمصدر `b2b_retailer_app` ويبدأ بحالة **جديد**. لا يصدر مخزوناً ولا ينشئ فاتورة تلقائياً، بل ينتظر تدفق المراجعة والتجهيز التجاري القائم.
