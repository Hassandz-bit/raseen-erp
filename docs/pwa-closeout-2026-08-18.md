# إغلاق تفعيل PWA العامة لـNawa ERP

أصبح لدى Nawa ERP الآن Manifest عام يبدأ من `/` ويعرّف التطبيق باسم Nawa ERP، ويحتوي على اختصارات للتجارة وفواتير المبيعات وNawa AI. نُقل تعريف Nawa Driver إلى `driver.webmanifest` منفصل كي لا يستبدل تطبيق ERP العام. يقدم `nawa-erp-sw.js` تجربة shell آمنة: يخزن صفحة التطبيق وأصول الواجهة العامة فقط، ويستبعد تماماً طلبات `/api/` وكل طلب غير GET من التخزين المؤقت.

| المجال | السلوك |
|---|---|
| عدم الاتصال | تظهر الواجهة المخزنة فقط؛ لا يعرض النظام أرصدة أو منتجات أو فواتير جديدة بلا اتصال |
| التحديث | تظهر رسالة تحديث عندما ينتظر Service Worker جديد، ويستطيع المستخدم تطبيقه صراحةً |
| الخصوصية | لا تخزن استجابات tRPC أو API أو طلبات الكتابة أو بيانات مؤسسة في Cache Storage |
| التثبيت | يظهر زر تثبيت عند إصدار المتصفح حدث `beforeinstallprompt`، مع بقاء التثبيت من قائمة المتصفح متاحاً عند غياب هذا الحدث |
| الكاميرا والطباعة | تظل الإذنات عند تفاعل صريح داخل الماسح وحوار الملصقات؛ لا تطلبها PWA تلقائياً |

## التحقق والحدود

تحققت استجابة `/manifest.webmanifest` و`/nawa-erp-sw.js` والأيقونة بنجاح. ظهر شريط التثبيت في معاينة الهاتف، وبقيت صفحات المنتجات وإدخال الباركود سليمة. نجح `pnpm check` و`pnpm lint` و**238 اختباراً في 104 ملفات**، ولم تسجل السجلات أخطاء متصفح أو طلبات فاشلة جديدة. 

لم يكتمل `pnpm build` داخل هذه البيئة، إذ نفدت ذاكرة Vite عند حد 768MB (رمز 134) أثناء تحويل اعتماديات التطبيق؛ لا يمثل ذلك خطأ TypeScript أو Service Worker، لكنه يمنع تأكيد حزمة الإنتاج من داخل sandbox. يلزم تنفيذ build/release في بيئة ذاكرة أعلى ثم فتح التطبيق المنشور ومنح إذن الكاميرا واختيار نافذة طباعة للتأكيد المادي النهائي.
